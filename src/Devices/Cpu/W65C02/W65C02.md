# W65C02

WDC W65C02S model. Driven by `CLK` (PHI2 in); `CLKout` mirrors it. No Bus Enable pin: BE assumed tied high. Datasheet: `docs/w65c02s.pdf` (`pdftotext -layout`; without `-layout` tables scramble). Reserved-opcode, NOP, RMW timing differences in Table 7-1 "Microprocessor Operational Enhancements" (around pages 29-30).

## Structure

- `W65C02::Logic` (`W65C02.hpp`) is `Sim::Device` adapter: copies pins into `Cpu::pins`, calls `Cpu::Next()`, drives A/D/RWB. `Cpu` (`W65C02Impl.hpp`/`.cpp`) is micro-op engine. Only `CLK` edge (stable trigger) does work.
- Each bus cycle is one micro-op (`void(*)(Cpu*)`) from 16-entry ring queue, invoked twice: address phase on PHI2 falling edge (`AddressPhase(addr, rw)` returns `true`; drive address, return) and latch phase on next falling edge (`LatchPhase(data)` returns sampled data; update registers here).
- Instruction handlers in `*Ops.hpp` `Enqueue` micro-ops built from `Addressing::` helpers. `EnqueueFront` inserts conditional cycles (page-cross fixups, RMW final write). Helpers shared by many opcodes: when auditing one, check every call site against addressing mode it claims.
- `InstructionMap.hpp` maps opcodes. Unmapped opcode defaults to `SystemOps::BRK`: unimplemented opcode runs BRK vector fetch from `$FFFE/$FFFF`, no failure.
- `DetermineNextInstruction()` picks next action when queue empty: RESB, then NMI (edge), then IRQ (if I clear), then opcode fetch.

## Bus profile

Encoded as `R` and `W` macros at top of `W65C02_lda_sta.devtest`.

- One bus cycle per `CLK` period. On each falling edge CPU samples `D` for cycle just ended, then presents next `A`/`RWB` (and `D` on write). New outputs appear one cycle later (stable-write lag), hence `step 2` after each edge.
- Read data must be on `D` at falling edge that ends cycle. Write data is on `D` for cycle it is presented.
- Read to write: after falling edge, `step`, `clear D`, `step`. Clearing in same resolve as CPU write avoids `CONTENTION` report.
- RESB checked when queue empty, on falling edge. Hold low through one falling edge, then release.
- Reset sequence in this model: two dummy reads of `$0000`, then vector low `$FFFC`, vector high `$FFFD` (4 cycles). Datasheet specifies seven.

## Registers (`DumpRegisters`)

`PC`, `A`, `X`, `Y`, `S`, `P`. Registers update at latch phase, i.e. falling edge that starts following cycle. To see effect of instruction's last cycle, include next cycle's call in script. `PC` is address of next byte to fetch. `S` (`0xFF`) and `P` (`0x34`) set by constructor; `PC`/`A`/`X`/`Y` undefined until reset sequence has run.
