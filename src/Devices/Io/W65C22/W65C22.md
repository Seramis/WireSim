# W65C22

Register-level model of WDC W65C22 Versatile Interface Adapter (VIA; `docs/w65c22.pdf`). Got two 8-bit bidirectional ports, per-bit direction control, optional input latching, two 16-bit interval timer/counters, 8-bit bidirectional shift register, IFR/IER interrupt handling with CA1/CA2/CB1/CB2 handshake lines.

## Pinout reference

| Pin | Direction | Description |
| --- | --- | --- |
| `D` (8-bit bus) | Bidirectional | Data bus |
| `PA` (8-bit bus) | Bidirectional | Peripheral port A; per-bit direction via DDRA |
| `PB` (8-bit bus) | Bidirectional | Peripheral port B; per-bit direction via DDRB. Bit 7 can be overridden by Timer 1's output. Bit 6 can be the Timer 2 pulse-counting input. |
| `RS` (4-bit bus) | Input | Register select, 0-15 (see the register map) |
| `CS1` | Input, active high | Chip select; both `CS1` and `CS2B` must be asserted for the chip to respond |
| `CS2B` | Input, active low | Chip select |
| `RWB` | Input | Read/write select: high = read, low = write |
| `PHI2` | Input | Bus clock. Gates register access and, in `TimerClockSource::ClkPin` mode, advances the internal timers. |
| `RESB` | Input, active low | Hardware reset |
| `IRQB` | Output, variant-dependent | Interrupt request, driven low while any enabled interrupt flag is set. `Variant::S` is push-pull (high when deasserted). `Variant::N` is open-drain, pull-down only (floating when deasserted). See "Variant". |
| `CA1` | Input | Port A control line 1: edge-triggered interrupt input and PA's input-latch trigger |
| `CA2` | Bidirectional, mode-dependent | Port A control line 2: input, fixed output, or handshake/pulse output, selected by PCR |
| `CB1` | Bidirectional, mode-dependent | Port B control line 1: interrupt input and PB latch trigger, or the Shift Register's clock line, depending on ACR's shift mode |
| `CB2` | Bidirectional, mode-dependent | Port B control line 2: interrupt input or handshake output selected by PCR, or the Shift Register's serial data line, depending on ACR's shift mode |

## Internal state reference

### Register map

`RS` picks one of 16 registers:

| RS | Read | Write | Notes |
| --- | --- | --- | --- |
| 0 | IRB | ORB | DDRB-gated per bit: output bits read back ORB, input bits read the pin (or latched IRB) |
| 1 | IRA | ORA | Reflects the latched IRA when latching is enabled, else the live pin. Also the CA2 handshake/pulse trigger (see Behavior). |
| 2 | DDRB | DDRB | |
| 3 | DDRA | DDRA | |
| 4 | T1C-L | T1L-L | Read clears IFR6. Write touches only the low latch (the counter reload happens on the $5 write). |
| 5 | T1C-H | T1L-H | Write loads both latches into the counter and starts it; clears IFR6 |
| 6 | T1L-L | T1L-L | No side effects either way |
| 7 | T1L-H | T1L-H | Write updates the latch only (no counter reload) but clears IFR6 |
| 8 | T2C-L | T2L-L | Read clears IFR5 |
| 9 | T2C-H | T2C-H | Write loads the counter (transferring the low latch) and starts it; clears IFR5 |
| A | SR | SR | Either direction clears IFR2 and re-arms the 8-shift counter |
| B | ACR | ACR | |
| C | PCR | PCR | |
| D | IFR | IFR | Write: a logic 1 clears that flag bit (0-6). Bit 7 is not a real flag. |
| E | IER | IER | Write: bit7=1 sets the bits named by 1s in 0-6, bit7=0 clears them. Read always reports bit7=1. |
| F | IRA | ORA | Same as register 1 without the CA2 handshake/pulse side effect |

### Auxiliary Control Register (ACR, register B)

| Bit | Name | Meaning |
| --- | --- | --- |
| 7 | T1 PB7 output enable | 0 = PB7 unaffected by T1; 1 = T1 drives PB7 |
| 6 | T1 free-run | 0 = one-shot; 1 = continuous (free-run) |
| 5 | T2 mode | 0 = interval timer; 1 = PB6 pulse counting |
| 4-2 | Shift Register mode | see the Shift Register mode table |
| 1 | PB latch enable | 0 = disabled; 1 = enabled |
| 0 | PA latch enable | 0 = disabled; 1 = enabled |

### Shift Register mode (ACR bits 4-2)

| Value | Mode |
| --- | --- |
| 000 | Disabled |
| 001 | Shift in, T2 rate |
| 010 | Shift in, PHI2 rate |
| 011 | Shift in, external CB1 clock |
| 100 | Shift out, free-running T2 rate |
| 101 | Shift out, T2 rate |
| 110 | Shift out, PHI2 rate |
| 111 | Shift out, external CB1 clock |

### Peripheral Control Register (PCR, register C)

| Bit | Name | Meaning |
| --- | --- | --- |
| 7-5 | CB2 control | 3-bit field, same encoding as CA2 control below |
| 4 | CB1 polarity | 0 = negative edge active; 1 = positive edge active |
| 3-1 | CA2 control | see the CA2/CB2 control table |
| 0 | CA1 polarity | 0 = negative edge active; 1 = positive edge active |

### CA2/CB2 control (3-bit field)

| Value | Mode |
| --- | --- |
| 000 | Input, negative edge |
| 001 | Input, negative edge, independent (an ORA/ORB access does not clear the flag) |
| 010 | Input, positive edge |
| 011 | Input, positive edge, independent |
| 100 | Handshake output |
| 101 | Pulse output |
| 110 | Fixed low output |

| --- | --- |
| 7 | Any enabled interrupt (read-only status on IFR; set/clear direction select on an IER write) |

## Variant

```cpp
enum class Variant { N, S };
W65C22(Sim::Platform*, Variant = S, TimerClockSource = ClkPin, double internalTickHz = 1'000'000.0);
```

W65C22N and W65C22S differ in ways docs in `docs/w65c22.pdf` (sections 3.4-3.9, 5.3, 5.4): bus-holding devices on most pins, PA/PB current limiting, output drive strength, AC timing. This logic-level model got none of them, cuz `LogicState` got no notion of drive current or analog hold voltage. One diff with digital-logic effect: `IRQB`'s output driver (2.14/3.5). `N` open-drain, pull-down only: releases (`LogicState::F`) when deasserted, relies on external pull-up for high level. `S` full push-pull driver, drives high when deasserted. Default `S`.

## Behavior

Chip select is `CS1=H && CS2B=L`. `PHI2` is bus's effective strobe, `Logic()` reacts in two passes.

- **Immediate:** while selected, `PHI2` high, drives `D` combinationally for read, or captures pending write's address and data; else releases `D` (only if read was driving it). Two trigger groups share pass: `CS1`/`CS2B`/`RWB`/`RS`/`PHI2` (bus access) and `CA1`/`CA2`/`CB1`/`CB2`/`PB6` (control-line edges, async, not tied to `PHI2`). `ProcessControlLineEdges()` runs only for latter, plus once after reset to record pins' starting levels.
- **Stable, on `PHI2` only:** commits write exactly once on settled falling edge, then, in `TimerClockSource::ClkPin` mode only, ticks T1, T2, PHI2-rate shift sub-modes by one step. Tick runs *before* that edge's own write commits. Datasheet says T1 starts decrementing on clock *following* load, so load and its first decrement are different edges. Ticking against pre-write state then applying load preserves that separation.
- Output pins (`PA`, `PB`, `CA2`, `CB1`, `CB2`, `IRQB`) redriven only when register or run-state bit they derive from changed.
- Register-read side effect (IFR clearing, `D` driving) visible immediately, cuz immediate pass resolves same cycle. Anything written only from **stable** branch (T1-driven PB7, CA2/CB2 handshake and pulse levels, chip-driven CB1 clock level, IRQB) resolves one cycle after edge that changed it. Check on *next* access.

**Ports.** PA reads latched IRA when PA latching (ACR bit 0) enabled, else live pin, whatever direction. PB's output-direction bits read back ORB regardless of pin loading. PB's input-direction bits read pin or latched IRB, depending on PB latching (ACR bit 1).

**Timers.** T1, T2 use explicit "armed" flag instead of detecting 16-bit wraparound. One-shot timer sets interrupt flag once per load, free-run timer (T1 only) refires every `latch+1` ticks. T2 got no free-run mode; always one-shot, either PHI2-interval or PB6 pulse counting. PB7's square wave starts low after free-run load, same as one-shot case.

**CA2/CB2 handshake and pulse output.** Triggered by *any* access (read or write) to ORA/ORB (register 1 or 0; not no-handshake alias at register F), cuz register-level access can't tell Read-Handshake Data-Taken acknowledgement from Write-Handshake Data-Ready pulse. Pulse mode auto-deasserts on next PHI2 falling edge.

**Shift Register.** Bit 7 goes out first, rotated back into bit 0 on shift-out. Bits enter bit 0 first, shift toward bit 7 on shift-in. T2-rate sub-modes (001/100/101) use internal divider seeded from T2 low latch. Modes 001/010/101/110 stop after 8 pulses till SR register access re-arms them; 011/111 (external CB1 clock) and 100 (free-run) never stop. CB1's ordinary interrupt-edge and input-latch role suppressed whenever chip drives CB1 as shift clock (modes 001/010/101/110). CB2's interrupt-edge role suppressed likewise whenever active SR mode took CB2 over as serial data line.

**Reset.** RESB clears ORA, ORB, DDRA, DDRB, ACR, PCR, IFR, IER, synthesized CA2/CB2 levels. T1, T2 (counters and latches), Shift Register **not** cleared. Disabled while RESB reads low, cuz `Logic()` returns before any tick or shift can run.

## Added features

### Timer clock source

```cpp
enum class TimerClockSource { ClkPin, InternalThread };
W65C22(Sim::Platform*, TimerClockSource = ClkPin, double internalTickHz = 1'000'000.0);
```

T1, T2, PHI2-rate shift sub-modes (010/110) need something to call `Tick()` once per clock cycle. Two sources:

- **`ClkPin`** (default): `Tick()` runs from real `PHI2` pin's falling edge on simulation thread. Matches real chip, but wall-clock rate depends on how fast simulation runs. Fine for bus timing, but PB7 square wave used as audio tone wavers audibly if simulation's cycle rate fluctuates.
- **`InternalThread`**: dedicated thread sleeps to fixed-timestep schedule at `internalTickHz`, each wakeup calls `Platform::Enqueue([this]{ Tick(); })`. Never touches device state or nets directly, so `Tick()` always runs on simulation thread. `Logic()`'s stable branch skips its own `Tick()` in this mode. Bus access still reacts to `PHI2` as in `ClkPin` mode; only timer and shift advancement decoupled. Thread adds interval to next wakeup time instead of resetting from current time, so late wakeup (OS scheduling jitter) caught up by back-to-back `Enqueue()` calls, long-run average tick rate stays stable. Don't promise jitter-free timing for any individual tick.

Only T1, T2, PHI2-rate shift advancement depend on this choice. Bus access, CA1/CA2/CB1/CB2 edges, T2 pulse counting from PB6, external-CB1-clocked shift modes react to own pin whichever source selected.

## Limitations

- **T1L-H read ($07)** modeled as plain latch read, no side effect. Datasheet's wording for that row ("8 bits from T1 high order counter") appears to repeat $05 counter row above it by mistake.
- **Shift Register T2-rate sub-modes** use independent internal divider seeded from T2 low latch, not T2's own counter, so enabling one don't interact with T2's interval timeout.
- **CA2/CB2 pulse-output width** is one PHI2 cycle, not datasheet's AC-timing pulse width.
- **`TimerClockSource::InternalThread`** depends on host OS's thread-scheduling granularity (see above).
- **N/S differences other than `IRQB`'s driver type** (bus-holding devices, current limiting, drive strength, AC timing) not modeled.

## Test coverage

`W65C22.devtest` (default `S` variant, `ClkPin` source) covers:

- DDR-gated PA passthrough, output drive.
- T1 one-shot load, fire, wrap, no-refire.
- T1 free-run PB7 square wave (two full toggles).
- T2 one-shot, PB6 pulse counting.
- CA1/CA2 handshake output assert, deassert.
- Shift Register PHI2-clocked shift-out: full 8-bit rotation back to original byte, stop-until-rearmed behavior after 8 shifts.
- RESB hardware reset that clears ACR, IER but preserves canary byte written into SR beforehand.

Verified ad hoc with `DeviceHarness`, not in committed `.devtest`:

- **`variant=n`:** idle `IRQB` reads `F`. T1 interrupt (IER bit 6 set, T1 loaded with latch 1, ticked) pulls it to `L` one cycle later, clearing IFR6 releases it to `F`, not `H`. Same script with `variant=s` shows idle `IRQB` reading `H`. Duplicates committed T1-interrupt coverage, only checks other driver type.
- **`clock=internal`:** repeated `PHI2` edges leave T1's counter unchanged, so `ClkPin` tick path disabled in this mode. With `sleep <ms>` verb at `internalTickHz=2000`, T1's counter decremented by exactly 100 counts over 50 ms. Exact count over wall-clock sleep depends on host scheduling, so not safe regression assertion.

Not exercised by script: Shift Register input modes (001/010/011), T2-rate output mode (101). Rotation test exercises shift mechanics (bit ordering, 8-count stop, rearm) through mode 110 only, full rotation returning to starting value reasonable proxy for bit-ordering logic shared by all modes. External-CB1-clock modes (011/111), T2-rate divider sub-modes (001/100/101) implemented but unverified by script.
