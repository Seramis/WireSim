# SST39SF010

128K x 8 sector-erase flash (SST39SF010A), modeled as ROM. Reads work like SRAM (standard JEDEC byte-wide pinout). Contents are given once at construction and never change.

## Pins

| Pin | Direction | Notes |
| --- | --- | --- |
| `A` | in | 17-bit address bus, A0-A16 (131,072 bytes) |
| `D` | output only here | 8-bit data bus, DQ0-DQ7; driven on read, released (`F`) otherwise |
| `NotCE` | in | chip enable |
| `NotOE` | in | output enable |
| `NotWE` | in | here for pinout fidelity; writes are ignored (see below) |

Read condition: `NotCE` and `NotOE` low, `NotWE` high drive `D`; otherwise `D` is released. A `NotWE` pulse while `NotOE` is low is not a read cycle.

## Contents are a constructor argument

The image is a `std::vector<uint8_t>` of up to 131,072 bytes. A shorter image is padded with `0xFF`, the read value of an erased cell.

A low pulse on `NotWE` while `NotCE` is low is detected and, in debug mode, logged as an ignored write attempt. Contents never change.

## Register inspection

Implements `Sim::IMemoryInspectable`: `Peek`/`Poke` address the whole 128 KiB image directly, with no pins or timing involved.

## Limitations

- No write support: byte program, sector erase, chip erase, software ID entry/exit and the toggle-bit and DQ7 status polling are not modeled.
- No access-time or command timing. Reads resolve combinationally, no propagation delay.

## DeviceHarness

`contents=@path` loads a ROM image file. `contents=<literal>` loads literal bytes, handy for a short inline pattern. Omitting it leaves the chip all `0xFF`. `SST39SF010.devtest` covers programmed and unprogrammed reads across the full address range, bus release on deselect and output disable, an ignored write attempt, a write pulse with `NotOE` low, and inspection.
