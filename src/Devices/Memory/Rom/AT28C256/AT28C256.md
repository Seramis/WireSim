# AT28C256

32K x 8 paged-parallel EEPROM, model as ROM. Read work like SRAM (standard JEDEC byte-wide pinout). Content given once at construct time, never change after.

## Pins

| Pin | Direction | Notes |
| --- | --- | --- |
| `A` | in | 15-bit address bus, A0-A14 (32,768 bytes) |
| `D` | output only here | 8-bit data bus, I/O0-I/O7; drive on read, release (`F`) otherwise |
| `NotCE` | in | chip select |
| `NotOE` | in | output enable |
| `NotWE` | in | here for pinout fidelity; write get ignore (see below) |

Read condition (per datasheet): `NotCE` and `NotOE` both low drive `D`; otherwise `D` release to high-Z.

## Contents are a constructor argument

Image get pass to constructor as `std::vector<uint8_t>` of up to 32,768 bytes. Shorter image get pad with `0xFF`, read value of erased cell.

`NotWE` low pulse while select get detect and, in debug mode, log as ignored write attempt. Content never change. Real write cycle also need `NotOE` high, which read condition already exclude, so no separate guard need to keep write pulse from driving bus.

## Limitations

- No write support: byte write, page write, software data protection, DATA polling, toggle bit not model.
- No access-time (`tACC`) or page-write timing (`tBLC`, `tWC`). Read resolve combinationally, no propagation delay.
- Extra 64-byte identification region not model.

## DeviceHarness

`contents=@path` load ROM image file. `contents=<literal>` load literal bytes, handy for short inline pattern. Omit it leave chip all `0xFF`. See `AT28C256.devtest`.
