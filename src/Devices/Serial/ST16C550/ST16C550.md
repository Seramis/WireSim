# ST16C550

Model register-level behavior of Exar ST16C550 UART (`docs/st16c550_501_040605.pdf`). Not model serial bit stream (see "Byte-level, not bit-level"), not hardware autoflow control of newer 16C550-family parts like TL16C550C; chip has none (see "RTS/CTS flow control").

## Register map

`A` (3-bit) select register. DLAB = LCR bit 7 (`IsDlab()`).

| A | Read | Write | Notes |
| --- | --- | --- | --- |
| 0 | RHR / DLL | THR / DLL | DLL/DLM only when DLAB=1 |
| 1 | IER / DLM | IER / DLM | |
| 2 | ISR | FCR | |
| 3 | LCR | LCR | always addressable regardless of DLAB |
| 4 | MCR | MCR | DTR/RTS/OP1/OP2 bits stored and readable; RTS drives flow control. No `-DTR`/`-OP1`/`-OP2` pins. LOOP (bit 4) implemented at byte level (see "Loopback"). |
| 5 | LSR | — | write reserved, same as real chip |
| 6 | MSR | — | write reserved, same as real chip |
| 7 | SPR | SPR | |

Chip select = `CS0=H && CS1=H && NotCS2=L`, same as real pinout. Both active-high (`IOR`/`IOW`) and active-low (`NotIOR`/`NotIOW`) strobe pins accepted, matching datasheet's "tie unused one to inactive level".

Write fires once per strobe assertion. Writes edge-detected in software (`isWriteStroke = isWrite && !_lastIsWrite`) instead of re-applied each immediate-loop re-evaluation (see `overview.md`).

## Reset

`RESET` level-sensitive, like real chip's `-MR` pin. Device re-inits on every `Logic()` call while `RESET` reads high (registers and FIFO cleared, `D` and `INT` released), resumes register dispatch once it reads low.

`Logic()` checks pin's level (`Pins.RESET.IsHigh()`) not which trigger bit fired. `Platform` can batch RESET's trigger with unrelated register-access trigger in one call (e.g. one-time settle every pin gets from `Platform::Link` before first cycle). Gating on trigger bit would silently drop that register access when two coincide.

## Loopback (MCR bit 4)

Setting MCR.LOOP diverts device's byte path back onto itself, per datasheet's "Loop-back Mode":

- `WriteTHR()` pushes written byte straight into `_rxFifo` (through shared `PushRxByte()` helper, same overrun-on-full behavior as normal `Receive()`) instead of calling `Send()`. Nothing reaches external `Terminal` while looped.
- `Receive()` (inbound bytes from connected peer) ignored, matching datasheet's disconnection of pins. Peer still sending during loopback has bytes dropped, not queued.
- `ReadMSR()` mirrors MCR's four output bits onto MSR's four input bits (CTS←RTS, DSR←DTR, RI←OP1, DCD←OP2) instead of fixed `0xB0`. Delta bits (MSR 0-3) stay 0 both modes.
- `UpdateFlowControl()` forces externally visible RTS (propagated through `UpdateRTS()` / `Terminal::AddRTS`) to deasserted whatever MCR.RTS is, since RTS no longer reaches external line when rerouted internally. Only modem-control output with external effect in this model. A `NullModemConnect`-linked peer sees "not clear to send" either way.

Since model byte-level, no TSR/RSR shift register or serial timing to loop through: next register write lands in RX FIFO instead of going out. FIFO fill, trigger levels, overrun, timeout and interrupts then run same code paths as real inbound byte. Makes loopback useful for register-level `DeviceHarness` tests (see `ST16C550.devtest`): FIFO, interrupt and overrun behavior reachable through `IOR`/`IOW`/`A`/`D` alone, no wired-up `Terminal` needed.

## Byte-level, not bit-level

`ST16C550` inherits `Sim::Device` (netlist side: `A`, `D`, strobes, `INT`) and `Terminal` (byte-stream endpoint, see `Devices/Serial/Terminal.hpp`). `RX`/`TX` pins in `ST16C550Pins` vestigial; model never serializes bits onto them. Instead:

- `WriteTHR()` calls `Terminal::Send(b)`, queues byte for `Terminal`'s worker thread to hand to any listener added with `AddTX` (e.g. `TcpTerminal`, or other end of `Terminal::NullModemConnect`).
- Inbound bytes arrive through `Terminal::RX(b)`, then `Terminal`'s worker thread, then `ST16C550::Receive(b)`, pushes into `_rxFifo`.

So no baud-rate timing, start/stop bit or framing/parity error generation. Device trades bit accuracy for byte-accurate model driven by datasheet's register semantics.

## Register inspection

Implements `Sim::IRegisterInspectable`. `DumpRegisters()` exposes `IER`, `FCR`, `LCR`, `MCR`, `SPR`, `DLL` and `DLM`, plus three derived fields with no backing register: `RxFifoSize` (`_rxFifo.size()`), `OverrunError` and `InterruptPending` (0 or 1). RHR, THR, ISR, LSR and MSR not included. Reading them has side effects (FIFO pop, error-bit clear, interrupt recompute) instead of exposing stored state, so dump would misrepresent what read does. Drive `A`/`IOR`/`D` through `Logic()` to observe those.

## Threading and locking

Three threads touch device's state:

1. Sim thread, through `Logic()`.
2. `Terminal`'s RX-drain thread (see `Terminal.hpp` for why TX-dispatch and RX-drain separate threads), calls `Receive()`.
3. Device's `_timerThread` (`TimerLoop()`), 100 ms poll standing in for datasheet's `4 × wordlen + 12` bit-time RX timeout counter. Close enough for FIFO timeout behavior but not cycle-accurate.

`_uartMutex` serializes register and FIFO state across all three. `Receive()` and `TimerLoop()` call `UpdateInterrupts()` directly, writes `pins.INT` from outside sim thread. Deliberate exception to `Platform::Enqueue()` / `EnqueueWithFuture()` convention (root `AGENTS.md`, "External input"). Safe only because `INT` single boolean net with no fan-in from other devices to race against. `UpdateRTS()` (reached from `Logic()`, `Receive()` and `TimerLoop()` through `UpdateFlowControl()`) writes *peer* terminal's state directly from whichever thread called it, same caveat.

## Known simplifications

- `-DTR`/`-OP1`/`-OP2` stored in MCR but no netlist pins, no effect outside loopback. Only RTS does anything on line (see "RTS/CTS flow control"). Outside loopback, `ReadMSR()` returns fixed `0xB0` (CTS/DSR present, no deltas), since nothing drives this UART's CTS *input*: `TcpTerminal` consumes UART's RTS through its `CTS()` override but never calls `UpdateRTS()` itself.
- No transmit FIFO. `WriteTHR()` sends immediately, `ReadLSR()` always reports THRE/TEMT (bits 6:5) set. Nothing throttles TX direction. Device producing output faster than `TcpTerminal`'s 2048-byte backlog drains would overflow it (oldest bytes dropped silently).
- No parity, framing or break detection, so LSR bits 2-4 and 7 and line-status ISR source (`0x06`) never occur. Overrun (bit 1) implemented.
- `WriteFCR()` only clears RX FIFO (bit 1). TX FIFO reset (bit 2) and DMA mode (bit 3) unused since no TX FIFO or DMA signalling (`-RXRDY`/`-TXRDY` not modeled).

`GetTriggerLevel()` and ISR priority encoding (`0x01` none, `0x02` THRE, `0x04` RDA, `0x0C` timeout) match datasheet's Table 5 and FCR bit 7:6 trigger-level table.

## RTS/CTS flow control

Real ST16C550 has no auto-flow silicon. `-RTS` mirrors MCR bit 1, *driver* must deassert it before its receive buffer overflows and reassert once drained. This model keeps that division of labor, across two layers because of how bytes arrive here:

- **Firmware** manages MCR.RTS traditional way, from fill level of its own software ring buffer with high and low watermarks, from IRQ handler and read routine. Only layer real chip has, only one visible at register level (`ReadMCR`/`WriteMCR`).
- **Device** (`UpdateFlowControl`, called from `Receive()`, `ReadRHR()`, `WriteMCR()`, `WriteFCR()` and `Reset()`) additionally ANDs software request with its own `_rxFifo` occupancy (deassert at 4, reassert at 1, out of 16-byte capacity), independent of what firmware has done yet. Needed because of byte-level model: `TcpTerminal` delivers RX bytes at host-thread speed, can outrun *simulated* CPU between IRQs, so large paste could fill 16-byte FIFO before firmware's watermark logic ran. Real chip's receive rate capped by baud rate; this model's not, so gets safety net datasheet lacks.

Effective `-RTS` output (propagated through `UpdateRTS` / `Terminal::AddRTS` / `CTS`, not netlist pin) is AND of both layers. `TcpTerminal` treats peer's RTS as its CTS input (`TcpTerminal::CTS`), stops reading socket while deasserted, leaves bytes in kernel's TCP receive buffer, so nothing read then dropped. See `Terminal.hpp` for bounded relay queues (`MAX_PENDING`) and two-threads-per-direction design letting pause propagate end to end without deadlock, and `TcpTerminal.cpp`'s `RunServer` for non-blocking client socket, keeps `IsConnected()`'s liveness check from blocking thread that would otherwise flush backlog or honor resumed RTS.

RX FIFO overrun (byte arriving while FIFO already holds 16) sets LSR bit 1, drops byte, same as real chip. Flow control should make it rare but can't make it impossible under extreme latency. No line-status interrupt raised (IER bit 2 and ISR `0x06` unimplemented).
