# W65C51N

Register-level model of WDC W65C51N Async Comm Interface Adapter (ACIA; `docs/w65c51n.pdf`). Got single-byte buffer each direction (no FIFO), like real chip. Work byte level only: no serial bit stream, no baud-rate generator, no crystal clock modeled (see "Known simplifications").

## Register map

`RS1`, `RS0` pick register (datasheet Table 1): `addr = (RS1<<1)|RS0`.

| addr | Read | Write |
| --- | --- | --- |
| 0 | Receiver Data Register (RDR) | Transmitter Data Register (TDR) |
| 1 | Status Register | Programmed Reset (data don't care) |
| 2 | Command Register | Command Register |
| 3 | Control Register | Control Register |

Chip select is `CS0 = H && CS1B = L`. `RWB` high = processor read; low = write.

## Access model

Datasheet tie all data transfers to "PHI2 high period when selected", so `PHI2` be effective enable strobe. `Logic()` react two passes:

- **Immediate** (on `CS0`, `CS1B`, `RS0`, `RS1`, `RWB`, `DCDB`, `DSRB`, `PHI2`): while selected and `PHI2` high, drive `D` combinationally for read, or capture bus master addr+data for pending write. Read's clear-on-read side effects (RDR's `RDRF`, Status Register's latched IRQ bit) applied here, in `DriveRead`. Safe to re-run on every settle iteration cause each only set flag to `false`.
  - Idle call return before taking lock: no access in progress, `D` not driven, no write waiting to commit, no `DCDB`/`DSRB` change, nothing changed by `Receive()` since last redrive. Output pins redriven only when state they derive from change.
- **Stable, on `PHI2` only:** commit write exactly once, on settled falling edge, using addr+data immediate pass captured (`CommitWrite`: TDR send, Programmed Reset, Command and Control register updates). Write need once-per-pulse guarantee cause side effects not idempotent (`Send()` must transmit byte exactly once).

Output pin that change only through `CommitWrite` (`DTRB`/`RTSB` after Command Register write) therefore show new value one PHI2 pulse after write. Check it on *next* access, not one that did write. `IRQB` clearing on Status Register read got no such lag, cause immediate pass handle it.

`RESB` is level-sensitive: `Logic()` check `Pins.RESB.IsLow()` and re-init while it read low, instead of react only to call that carry its trigger bit.

## Pin behavior

- **IRQB** true open-drain, like datasheet say ("open drain output, permitting several devices to be connected to the common IRQB... input"). Assert strong low, float (`F`) otherwise. No pull-up modeled, so idle `IRQB` read `F`; external pull-up give high level on real board.
- **DTRB** and **RTSB** driven combinationally from Command Register (`DriveOutputs`), recomputed every `Logic()` call. RTSB low for TIC = `10`/`11` (Command bit 3 set), high for `00`, also held high while RDR full (see "Flow control").
- **DCDB** and **DSRB** are inputs. Status Register mirror their current level, edge on either raise interrupt (gated by Command Register bit 1, IRD). See "Known simplifications" for how mirrored bits differ from datasheet's timing.

## Flow control

Chip is `Terminal` (`Devices/Serial/Terminal.hpp`), so RTS and CTS cross to host terminal through `UpdateRTS()` / `CTS()`, like any byte-stream peer, not through netlist pins.

- **RTS out.** State driving `RTSB` (Command TIC bits, RDR empty) also announced to terminal with `UpdateRTS()` whenever change. Terminal that honor RTS (e.g. `TcpTerminal`) stop reading from source while deasserted. Received byte drop it immediate from receive path, no wait for next bus cycle. Reading RDR raise it again next `Logic()` call. After reset (Command = 0) stay deasserted till firmware set TIC.
- **CTS in.** Peer's RTS arrive in `CTS()`. Transmitter enabled only while `CTSB` low and peer clear to send; else TDR write dropped (see below). Peer that never announce RTS count as clear to send.
- **No byte lost to fast sender.** Terminal stop at most few bytes after RTS fall, those already in its relay queues. `Receive()` run on terminal's RX-drain thread, may block, so wait till RDR read (or chip reset or destroy) then store byte. Back-pressure travel to sender through `Terminal::RX`. OVRN (Status bit 2) therefore always read 0.

## Known simplifications

- **Byte-level, not bit-level.** Class inherit byte-stream transport (`Devices/Serial/Terminal.hpp`). `CommitWrite`'s TDR case call `Send()`, `Receive()` (invoked from transport's worker thread) fill one-byte RDR once empty. `TxD`, `RxD`, `RxC`, `XTLI`, `XTLO` declared pins but never driven or read. Control Register bits (word length, stop bits, baud rate, receiver clock source) stored and readable but inert.
- **FE/PE always 0.** Framing and parity detection need bit-accurate line, and datasheet say parity never enabled on this chip.
- **TDRE (status bit 4) always 1.** This datasheet's own behavior: TDR and TSR load together, so bit can't be polled to pace writes.
- **No transmitter interrupt.** Every Command Register TIC (bits 2-3) combo documented as "disabled" or "do not use", datasheet say "Transmitter Interrupt should never be enabled". No code path set interrupt latch for TDRE.
- **CTS gates whole write.** Real chip stall transmission till `CTSB` clear. With no shift register to stall, TDR write made while `CTSB` high, or while peer not clear to send, get dropped (`Send()` not called) instead of queued.
- **Break (Command TIC = `11`) not modeled.** Behave like TIC = `10` (`RTSB` low). Nothing drive break condition onto `TxD`.
- **DCDB/DSRB status bits a direct, non-latching mirror of pins.** Datasheet freeze them at post-change level till Status Register read, then re-interrupt with newest level. Here interrupt edge-triggered, but status bits always show current pin level. Matter only if line change more than once within one access window.
- **`Receive()` never write pin direct.** Only mutate mutex-guarded state (and announce RTS to terminal), then raise atomic flag that make next `Logic()` call take locked path, which redrive `IRQB`, `RTSB`, `D`. With free-running `PHI2` that happen almost immediate. In standalone test with no clock running, `step` `PHI2` after anything that change state from outside `Logic()` before expecting pins to reflect it.

## Test coverage

`W65C51N.devtest` cover Command and Control register round trip, Programmed Reset, hardware reset through `RESB`, Status Register's `DSRB`/`DCDB` mirroring and edge-triggered interrupt, and `DTRB`/`RTSB` tracking Command Register (TIC bits, not echo bit).

Registration shim wire chip to scripted peer terminal: `device W65C51N rx=<bytes>` feed one byte per rising edge on `HostSend`, `HostRTS` driven low is peer's RTS deasserted, `expect reg.TxBytes` / `TxLast` / `AciaRtsReady` read what peer saw. With it, script cover transmitted byte reaching peer, received byte dropping announced RTS, second byte held while RDR full and delivered after read (OVRN stay 0), RTS rising again once RDR empty, peer's RTS gating transmitter.

Not covered: interrupt a received byte raise, and destructor's wake-up of stalled `Receive()` beyond clean exit.
